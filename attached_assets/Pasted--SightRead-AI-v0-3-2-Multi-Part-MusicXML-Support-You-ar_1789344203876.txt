# CURRENT PROBLEM

At present, importing a MusicXML file containing multiple `<part>` elements produces:

"This page needs another score.

This score contains multiple parts. Practice playback currently supports one part at a time."

This restriction is now too aggressive.

Real MusicXML files frequently contain multiple parts.

The MusicXML example set at:

https://www.musicxml.com/music-in-musicxml/example-set/

contains realistic multi-part and complex scores.

SightRead should accept these scores rather than rejecting the entire document merely because multiple parts exist.

---

# IMPORTANT MUSICXML DISTINCTION

Do NOT confuse:

* Score
* Part
* Staff
* Voice

A piano part can contain multiple staves and voices.

For example:

Score
└── Part: Piano
├── Staff 1: Right hand
├── Staff 2: Left hand
└── Voices

An ensemble could instead contain:

Score
├── Part: Violin
├── Part: Viola
└── Part: Cello

Therefore:

**Do NOT implement "every staff = a part".**

**Do NOT implement "every voice = a part".**

Use the actual MusicXML `<part>` and `<score-part>` relationship.

# REQUIRED V0.3.2 BEHAVIOR

## Single-part MusicXML

If the file contains one part:

* Preserve current behavior.
* Automatically use that part for playback.
* Do not require a new selector.
* Existing demo score must continue working.

## Multi-part MusicXML

If the file contains multiple parts:

1. Accept the MusicXML.
2. Parse the available parts.
3. Render the complete score using the existing OpenSheetMusicDisplay integration.
4. Identify each part by its MusicXML metadata.
5. Show a simple "Practice Part" selector.
6. Default to the first valid/playable part.
7. Allow the user to select another part.
8. Convert only the selected part into the existing playback representation.
9. Send that selected part to the existing MusicalPlaybackEngine.
10. Do NOT implement simultaneous multi-part playback in v0.3.2.
